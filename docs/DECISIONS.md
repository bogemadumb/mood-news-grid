# Решения и проверки

Датированный журнал: что пробовали, что оказалось правдой, что выбрали. Пишется по ходу работы,
а не задним числом. Отрицательные результаты остаются здесь наравне с положительными.

---

## 15.08.2026 — Стек

Python 3.12 + FastAPI + Jinja2, SQLite, natasha + pymorphy3 для русской морфологии.

Почему Python, а не JS: главная фишка проекта — извлечение фактов из русского текста
(имена, организации, топонимы, цитаты со спикером). Библиотек такого уровня для русского
языка в JS-экосистеме нет; natasha и pymorphy3 существуют только в Python. Держать
конвейер на Python, а веб на Node означало бы два рантайма ради вкусовщины.

Почему без сборки фронта: «как запустить» должно умещаться в три команды. node_modules,
бандлер и версия Node — три лишних способа сломать запуск на чужой машине.

## 15.08.2026 — `setuptools<81` в зависимостях

natasha тянет pymorphy2, который импортирует `pkg_resources`. В setuptools 81+ этот модуль
удалён, и `import natasha` падает с `ModuleNotFoundError`. Пин обязателен, это не перестраховка.

## 15.08.2026 — `text2num` откачен с 3.0.2 на 2.5.2

Обратная конвертация числительных прописью нужна, чтобы тон «бережно» мог написать
«почти три с половиной миллиарда» и не провалить проверку фактов.

Поставилась версия 3.0.2 — переписанная на Rust. Русский из неё выпал:

```
alpha2digit('двадцать пять', 'ru') -> ValueError: unsupported language ru
alpha2digit('twenty five', 'en')   -> 25
```

В 2.5.2 русский на месте (`ru` есть в списке языков). Пин `>=2.5,<3`.

**Известное ограничение 2.5.2, найдено сразу:** составные величины со шкалой конвертируются
неправильно.

```
'почти три с половиной миллиарда рублей' -> 'почти 3 с половиной 1000000000 рублей'
'двадцать пять процентов'                -> '25 процентов'      (верно)
'сто сорок восемь человек'               -> '148 человек'       (верно)
```

То есть «три миллиарда» не сворачивается в 3 000 000 000, а дробь «с половиной» не понимается
вовсе. Простые числительные работают. Для составных нужен свой постпроцессор поверх библиотеки —
это задача этапа 3, а не повод отказываться от библиотеки.

## 15.08.2026 — Переписывание идёт через подписку Claude, а не через платный API

z.ai зарегистрирован, ключ выпущен и валиден: `GET /v4/models` отдаёт девять моделей,
включая glm-5.2. Но любой вызов генерации возвращает `1113 Insufficient balance or no
resource package` — бесплатного тарифа у международного z.ai нет, нужен платёж.
Проверены на всякий случай и мелкие модели (`glm-4.5-air`, `glm-5-turbo`) — та же ошибка;
`glm-4-flash`, который раньше был бесплатным, теперь отвечает `1211 Unknown Model`.

Решение заказчика: использовать его подписку Claude, уже заведённую на сервере
(годовой OAuth-токен в `/opt/claudebot/token`).

**Что это значит архитектурно.** Витрина предгенерируется пакетно и лежит в SQLite,
сайт только читает — посетитель никогда не ждёт модель. Поэтому прогон переписывания
живёт отдельной задачей под пользователем `agent`, у которого есть токен, а веб-сервис
остаётся под изолированным `mood`, которому до токена не достучаться. Изоляция не ломается.

**Что осознанно НЕ делаем.** Публичную кнопку «перепиши своим тоном», которую жмёт любой
посетитель, на подписку не вешаем: это была бы раздача личного доступа третьим лицам,
а долгоживущий токен оказался бы за публичным сайтом. Живая генерация — либо на локальной
модели, либо на настоящем API-ключе, когда он появится.

**Что это значит для сдачи.** Проверяющий не сможет воспроизвести генерацию: подписки у него
нет. Поэтому провайдер в коде абстрактный — один интерфейс, за ним `claude-cli`, локальная
модель через LM Studio или Ollama и любой OpenAI-совместимый API. В README прямо написано,
как подставить свой ключ и повторить прогон.

**Сквозная проверка, 15.08.2026.** Реальная новость про ставку ЦБ, тон «иронично»:

```
модель вернула валидный JSON без markdown-обёртки
фактчекер: PASS, FPI 100.0, жёстких нарушений 0, мягких 0
галлюцинации: нет, потерянных хеджей: нет, добавленных усилителей: нет
стилистическая дистанция: 0.39 (порог отсечения копипасты 0.15)
```

То есть цикл «сбор -> переписывание -> проверка фактов -> вердикт» работает целиком
на настоящих данных, а не на выдуманном примере.

**Локальные модели, что есть в наличии:** LM Studio с `huihui-qwen3.5-9b-abliterated` (сервер
поднимается командой `lms server start`), Ollama с `qwen3.5:4b` и `gemma3:4b`. Пойдут офлайн-
фолбэком и строкой в лидерборде.

## 15.08.2026 — Детектор отрицаний переписан: глобальный счётчик частиц не работает

Первая версия сравнивала количество частиц «не» и «ни» в оригинале и в переписанном тексте.
На живых прогонах это оказалось непригодно.

Спортивная новость про бронзу Мельниковой, тон «иронично». В оригинале отрицаний **ноль**.
Модель три попытки подряд писала корректный текст и три раза получала отлуп:

```
попытка 1  FAIL  FPI=100.0  дистанция 0.25   «решила не отвлекаться по мелочам», «это уже не сенсация»
попытка 2  FAIL  FPI=100.0  дистанция 0.15   «как будто медалей у неё и так было мало»
попытка 3  TOO_LONG         дистанция 0.32   (на третьей попытке текст просто распух)
```

Все числа, имена, места и результаты на месте — FPI 100 в каждой попытке. Проблема в том,
что отрицание для иронии это родная конструкция, а не признак искажения.

**Как теперь.** Сравнивается не количество частиц, а привязка отрицания к сказуемому.
По синтаксическому разбору собираются два множества: глаголы с отрицанием и глаголы без него.
Нарушением считаются ровно два случая, оба про один и тот же глагол:

- отрицание пропало: «не смогли договориться» → «смогли договориться»;
- отрицание появилось у глагола, который в оригинале шёл без него.

Отрицание при новом глаголе, которого в оригинале не было, — стилистика, а не подлог.

Проверка на трёх контрольных случаях:

```
ирония добавляет отрицание к новому глаголу   -> PASS   (было FAIL)
отрицание пропало у того же глагола           -> FAIL   negation_dropped: смочь
отрицание появилось у того же глагола         -> FAIL   negation_added: смочь
```

Регрессия: все 17 кейсов прототипа по-прежнему классифицируются верно. Те же три новости
после правки проходят с первой попытки, FPI 100, дистанция 0.16–0.34.

Вывод, который пойдёт в README: метрика, придуманная за столом, и метрика, выжившая на живых
текстах, — разные вещи. Проверка обязана отличать стиль от подлога, иначе она просто
запрещает переписывание.

## 15.08.2026 — Порог непохожести должен быть свой у каждого тона

Второй гейт (не копипаста ли это) сначала был единым: 0.15 для всех тонов.
Первый же прогон нейтрального тона дал `COPY` с дистанцией 0.07.

Это не сбой модели, а свойство материала: новостная заметка уже написана нейтральным
языком. Нейтральный пересказ нейтрального текста обязан быть похож на оригинал —
требовать от него 15% непохожести значит требовать перефразирования ради перефразирования,
а это прямой путь к искажению фактов.

Порог вынесен в таблицу `moods` отдельным полем: нейтральный 0.06, эмоциональные 0.15.
Для эмоциональных тонов похожесть на оригинал по-прежнему означает, что модель не сделала
работу, и там планка не опускается.

## 15.08.2026 — Экран сравнения

Две колонки, между ними парная подсветка: наведение на факт слева зажигает его двойника
справа. Подсвечиваются только факты, которые проверка нашла в обоих текстах — подсветить
«пропавший» факт справа физически нечем, и рисовать там что-то было бы враньём.

Весь HTML с подсветкой собирается одной функцией `render_spans`, и это единственное место
в проекте, где строится разметка из данных. В шаблонах нет ни одного `|safe`. Причина:
заголовки и тексты приходят из интернета на публичный сайт. Тест проверяет, что строка
`<img src=x onerror=alert(1)> … </mark><script>alert(2)</script>` не порождает ни одного
живого тега, кроме наших.

Мелочь, которая была видна на первом же экране: подсветка цитаты обрывалась посреди слова
(«…беспилотными лета|тельными»), потому что цитаты попадают в отчёт обрезанными до 40 знаков.
Подсветка теперь дотягивается до конца слова.

## 15.08.2026 — Сверка спикера цитаты падала на падежах

Пакетный прогон 20 пар: 13 опубликовано, 7 забраковано. В логе бросилось в глаза сообщение,
которое не может быть правдой:

```
изменено: «безответственным человеком и предателем» -> «безответственным человеком и предателем»
```

Слева и справа один и тот же текст. Разбор показал, что расходится не цитата, а её атрибуция:
natasha возвращает спикера в том падеже, в каком он стоит в предложении. В оригинале было
«по словам Санчеса» → спикер `Санчеса`, в пересказе «Санчес заявил» → спикер `Санчес`.
Сравнение шло по сырой строке, поэтому один и тот же человек считался подменённым,
цитата получала `speaker_changed` (жёсткое нарушение) и вариант не публиковался.

Починено: спикеры сравниваются по леммам, с допуском на сокращение до фамилии.
`Педро Санчес` и `Санчес` — один человек, `Санчес` и `Набиуллина` — разные,
потерянная атрибуция по-прежнему нарушение.

Отдельно подтвердилось, что настоящие искажения цитат ловятся: во второй попытке
грустного тона модель сократила длинную цитату многоточием «(…)», и это честно
зафиксировано как изменение — сокращение цитаты меняет то, что человек сказал.

Регрессия: 17 кейсов прототипа и 26 тестов проекта проходят.

## 15.08.2026 — Атрибуция цитаты: соцсеть приняли за говорящего

Продолжение истории со спикерами. После починки падежей статья про мадридский кризис
всё равно не публиковалась ни в одном тоне, и снова с сообщением вида «изменено X -> X».

Разбор дал неожиданное: спикером цитаты в **оригинале** записалось `X`. В тексте стоит
«Публикацию она разместила на своей странице в соцсети X. „Правительство позволило…“» —
и извлечение атрибуции взяло название площадки за говорящего. Модель в пересказе указывала
настоящего автора («Аюсо заявила») и получала за это жёсткое нарушение: наша собственная
разметка была хуже, чем результат модели.

**Что сделано.** Сравнение спикеров разведено на четыре случая, и нарушением считается
только один:

| в оригинале | в пересказе | вердикт |
|---|---|---|
| имя | другое имя | `speaker_changed`, жёстко |
| имя | то же имя (любой падеж, можно только фамилию) | норма |
| мусор или пусто | имя, которое есть в тексте оригинала | норма — модель восстановила из контекста |
| мусор или пусто | имя, которого в оригинале нет | `speaker_changed` — выдумала |
| имя | пусто | `speaker_lost`, мягко |

Мусором считаются обрывки короче трёх знаков и названия площадок публикации
(X, Telegram, VK и прочие).

**Вторая засада там же.** Сопоставление шло по леммам, а pymorphy3 принимает иностранную
фамилию «Аюсо» за прилагательное и лемматизирует её в «аюсый», тогда как в тексте лемма
осталась «аюсо». Множества не пересекались. Теперь в сравнение идут обе формы —
и лемма, и само слово в нижнем регистре.

**Результат на той же статье:** было 0 публикаций из 12 попыток, стало 9 из 12.
Оставшиеся три отказа законные: одна генерация вышла пустой (FPI 0, пропало всё),
две поймались на добавленных усилителях.

Регрессия: 17 кейсов прототипа и 28 тестов проекта проходят.

**Общий вывод трёх сегодняшних починок.** Все три дефекта — ложные срабатывания, ни одного
пропущенного искажения. Строгая проверка охотнее запрещает нормальный текст, чем пропускает
подлог. Поэтому на этапе оценки меряем не только полноту детектора, но и долю ложных
срабатываний на честных перезаписях — без второй цифры первая ничего не значит.

## 15.08.2026 — Рекламный хвост издания ломал публикацию на сервере

На сервере первый же прогон дал 0 публикаций из 13 попыток при том, что на ноутбуке
проходило около 70%. Модель работала штатно и отдавала корректный JSON — падала проверка.

Разбор одной пары: «пропавшие факты» это `org: РБК` и `org: Максе`. Оригинал заканчивается
строкой «Оставайтесь на связи с РБК в „Максе“» — рекламный хвост издания. Модель его
справедливо выбрасывала при пересказе, а проверка считала это утратой двух фактов
и браковала корректный текст.

На ноутбуке эффект был слабее просто потому, что в тамошнюю выборку попало меньше заметок
РБК с таким хвостом. Классическая ситуация «у меня работает».

Починено на этапе сбора: `strip_promo_tail` срезает хвост по явным маркерам
(«оставайтесь на связи», «подписывайтесь», «следите за нами», «больше новостей»,
«читайте также», «присоединяйтесь») и только в конце текста — в середине такие фразы
могут быть частью новости. Тест проверяет и срезание, и то, что обычный текст не трогается,
включая ловушку «подписка на сервис выросла на 12%».

Это уже четвёртый по счёту ложноположительный класс за день и первый, найденный только
на сервере: разные машины собрали разные новости, и дефект проявился лишь на одной выборке.

## 15.08.2026 — Арт-дирекция: редакционная полоса

Первая вёрстка была аккуратной, но безликой: карточки с тенями и скруглениями,
системный шрифт — «чистый CSS разработчика». Для работы, где половина впечатления
решается за пять секунд, этого мало.

**Направление: газетная полоса.** Засечный Literata, волосяные линейки вместо рамок,
тёплая бумага вместо белого листа, моноширинные метаданные капителью, асимметричный
грид с ведущим материалом на две колонки.

**Главное решение: настроение меняет набор, а не цвет кнопки.** У каждого тона свои
вес, оптический размер, наклон, интерлиньяж, плотность и температура бумаги:

| тон | вес | опт. размер | интерлиньяж | трекинг | бумага |
|---|---|---|---|---|---|
| нейтрально | 400 | 16 | 1.66 | 0 | обычная |
| радостно | 560 | 34 | 1.50 | −0.012em | теплее |
| грустно | 320 | 12 | 1.86 | +0.012em | холоднее |
| иронично | 430 | 20 | 1.62 | −0.004em | обычная, курсив |

Это и есть идея продукта, показанная средствами дизайна: одни факты, разный набор.
Каждая кнопка переключателя набрана своим тоном — разницу видно до клика.
Типографика хранится в таблице `moods` рядом с промптом: добавить пятый режим —
это строка в базе, а не новый макет.

Оригинал слева всегда набран нейтрально. Иначе сравнение нечестное: разницу нельзя
было бы приписать тону.

Шрифты локальные, 424 КБ, кириллические сабсеты переменных начертаний. Внешних CDN
нет ни одного — это требование модели угроз, а не эстетики.

## 15.08.2026 — Стили на сервере не грузились с самого начала

Обнаружено только когда впервые посмотрел на демо глазами, а не через `curl` и счётчик
карточек: страница отдавалась голым HTML без единого стиля.

Причина в связке nginx и `root_path`. В конфиге стояло `proxy_pass http://127.0.0.1:8040/;`
со слэшем на конце — nginx срезал префикс `/mood`, а приложение с `root_path='/mood'`
ожидало его в пути. Маршруты страниц при этом совпадали, а смонтированная статика
(`app.mount('/static', ...)`) отдавала 404. Поэтому проверки «страница открывается,
карточек 30» проходили, а сайт выглядел сломанным.

Починено убиранием слэша: префикс передаётся приложению целиком и снимается им самим.

Урок на будущее: HTTP-код 200 и число элементов в разметке не доказывают, что страница
выглядит как задумано. Смотреть глазами обязательно — на четвёртом этапе это станет
частью проверочного списка перед сдачей.
