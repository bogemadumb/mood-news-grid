# Решения и проверки

Датированный журнал: что пробовали, что оказалось правдой, что выбрали. Пишется по ходу работы,
а не задним числом. Отрицательные результаты остаются здесь наравне с положительными.

---

## 15.08.2026 — Стек

Python 3.12 + FastAPI + Jinja2, SQLite, natasha + pymorphy3 для русской морфологии.

Почему Python, а не JS: главная фишка проекта — извлечение фактов из русского текста
(имена, организации, топонимы, цитаты со спикером). Библиотек такого уровня для русского
языка в JS-экосистеме нет; natasha и pymorphy3 существуют только в Python. Держать
конвейер на Python, а веб на Node означало бы два рантайма ради вкусовщины.

Почему без сборки фронта: «как запустить» должно умещаться в три команды. node_modules,
бандлер и версия Node — три лишних способа сломать запуск на чужой машине.

## 15.08.2026 — `setuptools<81` в зависимостях

natasha тянет pymorphy2, который импортирует `pkg_resources`. В setuptools 81+ этот модуль
удалён, и `import natasha` падает с `ModuleNotFoundError`. Пин обязателен, это не перестраховка.

## 15.08.2026 — `text2num` откачен с 3.0.2 на 2.5.2

Обратная конвертация числительных прописью нужна, чтобы тон «бережно» мог написать
«почти три с половиной миллиарда» и не провалить проверку фактов.

Поставилась версия 3.0.2 — переписанная на Rust. Русский из неё выпал:

```
alpha2digit('двадцать пять', 'ru') -> ValueError: unsupported language ru
alpha2digit('twenty five', 'en')   -> 25
```

В 2.5.2 русский на месте (`ru` есть в списке языков). Пин `>=2.5,<3`.

**Известное ограничение 2.5.2, найдено сразу:** составные величины со шкалой конвертируются
неправильно.

```
'почти три с половиной миллиарда рублей' -> 'почти 3 с половиной 1000000000 рублей'
'двадцать пять процентов'                -> '25 процентов'      (верно)
'сто сорок восемь человек'               -> '148 человек'       (верно)
```

То есть «три миллиарда» не сворачивается в 3 000 000 000, а дробь «с половиной» не понимается
вовсе. Простые числительные работают. Для составных нужен свой постпроцессор поверх библиотеки —
это задача этапа 3, а не повод отказываться от библиотеки.

## 15.08.2026 — Кириллица в User-Agent ломает сбор молча

Первая версия `sources.yml` несла человеческий User-Agent с русским пояснением. Все шесть
источников вернули `UnicodeEncodeError: 'ascii' codec can't encode characters`, то есть ноль
запросов вообще ушло в сеть. HTTP-заголовки не переживают не-ASCII. User-Agent теперь только
латиницей.

## 15.08.2026 — Источники: что показала проверка

`make check-sources`, прогон с Мака:

| источник | код | записей | с текстом ≥400 знаков | доля | медиана |
|---|---|---|---|---|---|
| rbc | 200 | 30 | 29 | 97% | 1210 |
| lenta | 200 | 200 | 0 | 0% | — |
| kommersant | — | — | — | — | DNS не резолвится с Мака |
| nplus1 | 200 | 10 | 7 | 70% | 533 |
| naked-science | 200 | 20 | 0 | 0% | — |
| 3dnews | 200 | 63 | 23 | 37% | 465 |

**РБК подтвердился:** фид `rssexport.rbc.ru/rbcnews/news/30/full.rss` отдаёт полный текст прямо
в ленте, 29 записей из 30 годные. Страницу РБК скрести не нужно вовсе.

**Naked Science — предположение оказалось неверным.** Ожидалось, что `content:encoded` несёт
полный текст. Фактически `content` содержит 60 знаков (дублирует заголовок), `summary` — 171.
Текст добирается со страницы.

**Коммерсант жив, DNS сломан локально.** С Мака `dig` не отвечает вообще («no servers could be
reached»), через 8.8.8.8 адрес находится сразу (178.248.238.19), с сервера домен резолвится и
отдаёт 301. Диагноз — залипший системный резолвер macOS, известная болячка. Лечится
`sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder`. На сбор с сервера не влияет.

## 15.08.2026 — Каскад извлечения текста нужен, и вот доказательство

Замер на трёх свежих статьях каждого источника, три способа извлечения (знаков текста):

| источник | trafilatura | свой CSS-селектор | JSON-LD |
|---|---|---|---|
| lenta | 637–1205 | 637–1205 (`div.topic-body__content`) | нет |
| naked-science | **6689–9682** | 2442–6522 (`div.body`) | нет |
| 3dnews | 775–3098 | **2902–4818** (`div.article-entry`) | нет |

Универсального победителя нет: на Naked Science trafilatura обходит селектор в полтора-четыре
раза, на 3DNews селектор обходит trafilatura втрое. Поэтому в `sources.yml` у каждого источника
поле `prefer`, а не один глобальный экстрактор.

JSON-LD с `articleBody` не нашёлся ни у одного из трёх — ступень в каскаде оставляем, но
рассчитывать на неё нельзя.

Побочное наблюдение: материалы Naked Science длиной 6–10 тыс. знаков. В витрину (заметки
800–4000 знаков, оригинал показывается целиком) они не попадут — останутся в базе как источник
статистики.

## 15.08.2026 — Хостинг: подраздел существующего сайта вместо отдельной машины

Решение заказчика. Демо живёт на его действующем VPS (Хельсинки) как `bogemadumb.ru/mood/` —
подраздел сайта-визитки. Сертификат Let's Encrypt на домен уже есть и продлевается сам,
DNS не трогаем.

Что было предложено взамен и отклонено: отдельный VPS в РФ (~250 ₽/мес). Аргумент был в
изоляции — на текущей машине лежит живая сессия личного Telegram, почтовые скрипты к девяти
ящикам и бэкапы паролей, а мы ставим рядом публичный сайт с полем ввода.

Компенсация принятого риска: отдельный системный пользователь, `ProtectHome=yes`,
`ProtectSystem=strict`, белый список каталогов на запись, `NoNewPrivileges`, лимит памяти,
`limit_req` в nginx.

## 15.08.2026 — Гигиена сервера перед установкой

Было занято 83% диска (свободно 5,0 ГБ). Освобождено 2,8 ГБ (стало 7,8 ГБ, 73%):
журнал systemd ужат до 100 МБ и ограничен `SystemMaxUse=200M`, кэши apt/npm/pip/uv вычищены,
логи atop старше трёх дней и ротированные syslog/btmp удалены.

Побочный эффект: вместе с кэшами снесены браузеры Playwright у пользователя `agent` —
восстановлены `playwright install chromium` (114 МБ).

## 15.08.2026 — z.ai доступен, ранний вывод о его недоступности опровергнут

При подготовке плана было зафиксировано, что `api.z.ai` не отвечает: четыре попытки с двух
разных точек, TLS-приветствие уходит, ответа нет, таймаут 15–20 с. Вывод был — провайдера,
которого предложил работодатель, использовать нельзя.

Повторная проверка тем же днём это опровергает. Эндпоинт отвечает штатной ошибкой авторизации:

```
POST https://api.z.ai/api/paas/v4/chat/completions
  с Мака (Россия):      HTTP 401 за 0,90 с  {"error":{"code":"401","message":"token expired or incorrect"}}
  с сервера (Финляндия): HTTP 401 за 0,89 с  то же самое
POST https://open.bigmodel.cn/api/paas/v4/chat/completions
                        HTTP 401 за 0,39 с  {"error":{"code":"401","message":"令牌已过期或验证不正确"}}
```

401 с осмысленным телом означает, что запрос дошёл до приложения и не хватает только ключа.
Первый замер, судя по всему, поймал временный сбой либо бил не в тот путь.

Следствие: основной моделью для переписывания берём GLM от Z.ai — ровно ту, которую назвал
работодатель. Это единственная его персональная просьба в задании, и выполнить её лучше, чем
объяснять, почему не вышло. Cloud.ru остаётся запасным вариантом, а не основным.
